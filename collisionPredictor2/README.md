# Collision Predictor ver.2 — 時系列（TTC）判定版

Yahboom K230 向け衝突警告の「判定ロジックだけ」を作り直したものです。
YOLOモデルはデモ付属の学習済みモデル（`yolov8n_seg_320.kmodel`）をそのまま使います。**再学習は不要です。**

## ver1 の何が問題だったか

ver1 は1フレームの静止画判定でした（大きさ35%＋中央への近さ20%＋下端への近さ45%、しきい値0.72）。
そのため「大きく写っているが距離は変わっていない前走車」「駐車車両」「隣の車線のトラック」でも警告になっていました。

ver2 は判定を次に置き換えます。

**「自分の進路内にいて、速く近づいているもの」だけを警告する。**

## 判定の仕組み（tracker.py）

1. **追跡**: フレーム間でクラスが同じで枠が重なる（IoU ≥ 0.20）検出を同一物としてIDを付け、直近0.8秒の履歴（時刻・面積・中心・下端）を保持する。
2. **TTC推定**: 距離 Z の物体は 面積 A ∝ 1/Z² なので、`log(A)` の時間変化率 slope から
   `TTC = 2 / slope`（秒）が得られる。slope は履歴に対する最小二乗回帰で求めるため、YOLO枠の毎フレームのブレ（±10%程度）に強い。前フレームとの単純比較は使わない。
3. **警告条件（全部同時）**:
   - 0.5秒以上・8フレーム以上追跡できている
   - TTC < 2.2秒（注意は 3.5秒）かつ、平滑化した面積が窓の最初より1.30倍以上に増えている
   - 自車進路の台形内にある（遠方は狭く、画面下端では中央約44%幅）
   - 条件が連続3回成立したら確定（ALERT）。解除は TTC > 4.5秒と別しきい値（ヒステリシス）

## ファイル

| ファイル | 内容 |
|---|---|
| `tracker.py` | 判定モジュール本体。純Python（mathのみ）で、PCでもK230のMicroPythonでも同じコードが動く |
| `test_tracker_pc.py` | PC検証。合成検出データ6シナリオで判定をテストする |
| `run_tracker_on_csv.py` | 実動画からPCで作った検出CSV（`time_sec,x,y,w,h,class_id`）を流して、警告タイミング／誤警告回数を実機なしで評価する |
| `k230_integration.py` | ver1 本体への組み込み手順（差し替える3箇所の断片） |

## PC検証結果（2026-11-24 実施）

```
$ python3 test_tracker_pc.py
stationary large vehicle     PASS  alert_at=-
approaching in path          PASS  alert_at=2.25s (must be <= 2.80s)
approaching adjacent lane    PASS  alert_at=-
receding vehicle             PASS  alert_at=-
3-frame flicker              PASS  alert_at=-
stationary + approaching     PASS  alert_at=2.25s (must be <= 2.80s)
ALL 6 SCENARIOS PASS
```

「接近」シナリオは、一定速度で接近し4.0秒で衝突する想定で、**衝突の1.75秒前に警告が確定**しました。
ver1 なら即警告になっていた「大きくて静止した車両」では一切鳴りません。

注意レベル（黄）は目安表示で、回帰の性質上、接近の初期に点滅することがあります。ブザーを鳴らすALERT側は連続成立＋ヒステリシスで確定させるため、確定後は安定します。

## K230 への組み込み

`k230_integration.py` の手順どおり、ver1 のメインループで危険度計算の部分だけを tracker に差し替えます。カメラ・YOLO・ブザー・LED の動いているコードは触りません。

- `tracker.py` をメインスクリプトと同じ場所（SDカード）に置く
- 画面には最も危険な対象の `TTC / 成長倍率 / レベル` を表示する（調整時に必須）

## 実機での調整ポイント

| 症状 | 調整 |
|---|---|
| 警告が遅い | `ttc_alert` を 2.2 → 2.6 に上げる（回帰には約0.3〜0.5秒の遅れがあるため） |
| 隣の車線で鳴る | `tracker.in_ego_path()` の台形を狭くする。カメラの取り付け角度（光軸のずれ）を先に確認 |
| 駐車車両で鳴る | `growth_min` を 1.30 → 1.45 に上げる。自車が接近しているなら進路内では本来「危険側」なので、まず進路判定を確認 |
| 検出漏れで鳴らない | ここだけモデルの話。320入力では遠方の小さい車が限界。その場合のみ検出モデルの学習／640化を検討 |

## 限界（正直なところ）

- 自車速度が分からないため、「自車が止まっていて相手も止まっている」場合と「同速度で走っている」場合の区別は面積変化なし＝安全側で扱います（どちらも相対速度ゼロなので衝突しません）。
- カーブでは進路台形がずれます。直線路前提の簡易判定です。
- これは運転支援の実験デバイスであり、安全装置としての認証等とは無関係です。
